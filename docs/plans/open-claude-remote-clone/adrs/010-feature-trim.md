# ADR-010: 裁剪 OnboardingGuide 与钉钉通知

## 状态

已接受

## 背景

复刻范围上需要明确"做什么、不做什么"。在分析阶段识别了若干上游可选功能，由用户筛选保留与裁剪。

## 决策

裁剪以下两项功能不在复刻范围内：

1. **OnboardingGuide**（首次使用引导组件）
2. **钉钉通知**（DingtalkService + 配置 + 设置 UI Tab）

其余功能（包括 ANSI filter、多实例、attach、Web Push、IP 监控、拖拽排序、二维码、双 Ctrl+C）全部完整实现。

## 理由

### OnboardingGuide

1. 用户为单人自用场景，不存在"新手不知道如何上手"问题
2. README 已经覆盖必要的快速开始指引
3. 减少 ~217 行 UI 代码 + 引导状态判断逻辑

### 钉钉通知

1. 钉钉是国内特定 IM 生态，不具普适性
2. Web Push（保留）已能覆盖手机锁屏通知场景
3. SSRF 防护、域名白名单、Webhook 签名等钉钉专属安全代码可省
4. 减少 ~200 行后端 service + config + 前端 Tab UI

## 后果

- **正面**：缩减约 400 行代码，降低维护面
- **负面**：用户后期想加钉钉通知需自行扩展（设计预留了 `SessionController.set<X>Service()` 注入点，扩展成本可控）
- **中性**：通知扩展点保持开放——未来如需 Slack / Telegram / 飞书机器人，按相同模式接入即可

## 备选方案

- **保留全部功能**：放弃，违反 YAGNI
- **裁剪更多**（如 attach、Web Push）：放弃，用户明确要保留
