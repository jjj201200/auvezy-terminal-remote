# 阶段 1 — 基础设施

> 状态：✅ 已完成（2026-05-09）
> 不影响 0.6.x：本阶段只新增模块，不修改现有 worker 代码路径，纯加法。

## 目标

为 0.7.0 broker / worker 拆分准备「不依赖 http-proxy / 不依赖 worker 改造」的最底层模块。
本阶段交付物**编译过且单测全绿，但运行时尚未被 worker / CLI 调用**——这是为
阶段 2、3 提供可信底座，故意拒绝把"接进现网"的合并风险一起背。

具体做：

1. **共享 sessions store**（ADR-006 落地）
   - `~/.atr/sessions.json` 读写，每次直读不缓存
   - `withFileLock` 保护并发写
   - TTL 惰性过期（读出来再判，过期当未命中）
2. **broker.json 状态文件**（ADR-002 落地）
   - 写入 `{ pid, port, host, startedAt, version }`
   - 读出后用 PID 探活 + 可选 HTTP 探针判活
3. **broker server 骨架**（ADR-001 落地）
   - 独立 Express app + listen，仅含 `/api/health`
   - 启动时占用 `withFileLock(~/.atr/broker.lock)` 写 broker.json
   - 退出时清 broker.json
   - 命令行入口暂不接（阶段 2 在 worker ensure 时调用，阶段 6 service install 时再加 CLI 子命令）

不做：

- ❌ http-proxy 接入（阶段 3）
- ❌ `<base href>` 注入（阶段 4）
- ❌ X-ATR-Forwarded-* 头（阶段 3 反代时一并加）
- ❌ worker 改 loopback / cookie 改名（阶段 2）
- ❌ CLI 子命令 `atr broker start/stop/status`（阶段 6 一起做）
